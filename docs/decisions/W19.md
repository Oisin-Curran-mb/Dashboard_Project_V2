## 2026-10-16: the renumber

Owner: "make W?? Pending Actions to be changed into W19 as it going to replace
Actions and alerts as this being scrapped and this is new one."

### Where the "W??" came from

The developer review dropdown builds its labels from `VIEW_WNUM`, a kind to
W-number map, and falls back to the literal `"W??"` for any kind it does not
list. `pendingactions` was in none of the three runtime maps, so the dropdown
read `W?? Pending Actions (final, 3 sizes)`.

That absence was not cosmetic. `WIDGET_SWITCH` is keyed by W number, and
`widgetOn()` reverse-looks-up `WIDGET_KIND` and returns `true` for any kind it
cannot find. So before this change the widget **could not be switched off or
held out of a release at all**. Being W19 is what makes it governable.

| Map | What it now says |
|---|---|
| `WIDGET_SWITCH` | `W19:true` (Pending Actions), `W20:false` (Alerts & Actions) |
| `WIDGET_KIND` | `W19:"pendingactions"`, `W20:"alerts"` |
| `VIEW_WNUM` | `pendingactions:"W19"`, `alerts:"W20"` |

Per the owner's 6 October rule, nothing a reader sees gained a W number. The
widget is titled "Pending Actions" on screen; W19 appears only in banners, the
widget map, the spec inventory and the driver filename. The driver asserts both
halves of that.

### Alerts & Actions is scrapped but NOT deleted, and cannot yet be

Its registry rows were already commented out, so nothing of it is on screen.
Its **CSS is not dead**, though: Pending Actions renders inside `.al-`,
`.alb4-` and the whole `.al2-dp-` detail-pane family and declares none of them
itself. Deleting the Alerts block today would strip the live widget of most of
its styling.

So the number was freed and the code was kept. Its driver moved to
`_tools/w20-alerts.driver.js` and now asserts the scrapped state — no live
registry row, rows still commented out, switch still off — **plus the list of
classes Pending Actions borrows**, so the dependency fails loudly rather than
silently if that block is ever removed.

Deleting it properly means giving Pending Actions its own copies of roughly
twenty-five classes first. That is the next piece of work and it is not
started.

**Do not rename the borrowed classes.** Renaming `al2-dp-*` to `pa3-dp-*` was
tried on 13 October and broke the right-hand detail pane;
`_tools/one-off/fix-pending-actions-2026-10-13.py` opens by reverting it.

## 2026-10-16: the styling moves onto tokens

Owner: "make sure everything is using tokens on that new widget and make sure
it all clear ... dont change how the widget works but just the styling to use
token."

### It had no CSS region of its own

Its 58 lines of CSS sat **inside** the Alerts & Actions banner pair, which is
why the Alerts driver was the thing reporting "no raw colours in the CSS region
(got 18)": all 18 were these. One Alerts rule
(`.alb4-xw-left-panel .al-cat:last-child`) was stranded in the middle of the
run and went back beside its sibling.

Measured across the whole region before the change: **18 raw colour literals in
the Pending Actions run, zero in the 380 lines of Alerts CSS around it.** The
borrowed families were already fully tokenised, so this was a one-widget
problem.

### The tokens it referenced did not exist

The literals were mostly written as `var(--invented-name,#hex)`. Five of those
names are declared nowhere in this build:

| Name | Declared | Used |
|---|---|---|
| `--color-primary` | 0 | 3 |
| `--color-err` | 0 | 1 |
| `--surface-card` | 0 | 1 |
| `--surface-subtle` | 0 | 3 |
| `--surface-widget-hover` | 0 | 2 |

So the hex fallbacks were doing the rendering, and the widget looked tokenised
while not being so. `--surface-subtle` was given three different fallbacks
(`#f8f9fb`, `#f1f5f9`, `#f8fafc`), which is how you can tell nothing was
resolving. All five names are gone; the lint's T1 fell from 135 to 130, which
is exactly those five.

### The palette changed, deliberately

The owner's call this session was **"adopt the house palette"** rather than
declare the invented names with their current values. Making the widget
genuinely token-driven and leaving it looking identical were mutually
exclusive, because the rest of this build is not painted in `#2563eb` blue.

| Was | Now | Why that token |
|---|---|---|
| `#2563eb` accent | `var(--brand-300)` | the build's own brand blue, `#3a5aaa` |
| `#2563eb` focus outline | `var(--focusring-base)` | the shared focus-ring idiom |
| `#f0f4ff` / `#f8f9fb` / `#f1f5f9` / `#f8fafc` hover and subtle surfaces | `var(--wn-200)` | what `.al-hd:hover` uses; four literals collapse to one token |
| `#fee2e2` on `#b91c1c` error pill | `var(--red-10)` on `var(--red-100)` | matches `.al-cat.sev-err .al-count` |
| `#fef3c7` on `#92400e` warning pill | saffron-25 on saffron-500 | matches `.sev-warn .al-count`; the build has no `--sf-*` alias, so the saffron primitives are named directly |
| `#dc2626` / `#d97706` dots | `var(--red-100)` / saffron-300 | same two ramps |
| `#fff` panel | `var(--surface-sheet)` | it is a popover surface |
| `rgba(0,0,0,.13)` panel shadow | `var(--elevation-overlay)` | the driver bar forbids a raw `rgba()` even in a shadow |

**One declaration was deleted:** `.pa3-card-btn:hover` carried
`box-shadow:0 0 0 2px rgba(37,99,235,.12)`, a focus-coloured ring painted on
hover. There is no token for it, the raw `rgba()` is forbidden, and the element
already has a real focus ring on `:focus-visible`. It went, and `box-shadow`
left the transition with it.

### Size literals: only exact-value swaps

`font-size:32px/11px/10px` onto `--type-size-32/11/10`, the 2/4/6/8/12/16px
`gap` and `padding` steps onto `--gap-*` / `--padding-*`, and the panel's
`border-radius:12px` onto `--r`, which is itself unit-12. Every one of these is
provably invisible because the token carries the same value. Two inline
`font-size` literals in the JS followed (16px and 14px).

**Left literal on purpose**, because no token carries the value and changing it
would move geometry: the 9px/10px/14px paddings, `gap:10px`, the `99px` and
`50%` radii, the 320px panel width, the 300px and 340px max-heights, the
`.06em`/`.04em` letter-spacings, `font-size:13px` (the scale jumps 12 to 14) and
the 80/100/120ms transitions (`--dur` is 150ms, so naming it would change the
timing).

### Verified

Suite green at 3,870 assertions across 20 drivers, where the 16 October pull had
left it at 3,674 with two failures and a crash. In the browser the live surfaces
resolve to the intended tokens, measured rather than eyeballed: error pill
`rgb(250,239,239)` on `rgb(176,58,58)`, warning pill `rgb(254,242,222)` on
`rgb(124,83,36)`, queue panel on `rgb(255,255,255)` with
`rgba(24,27,43,0.08) 0 20px 48px -10px` and a 12px radius, group headers and
number chips on `rgb(249,247,245)`, the Queues link on `rgb(58,90,170)`. The
queue panel still opens and still lists its five rows. The review dropdown reads
**W19 Pending Actions**.

## Still open

- **This driver is styling and wiring, not behaviour.** The group tabs, the
  queue panel's row actions, the glance-card modal and the detail pane have no
  assertions beyond rendering without throwing. The widget arrived without a
  driver at all, so this is a start rather than a regression.
- **Alerts & Actions cannot be deleted** until this widget declares its own
  copies of the borrowed classes.
- `handover.html` still carries a `#w19` section titled Alerts & Actions, and
  `docs/Pics/Version 2/W19 - Alerts & Actions/` still has that folder name.
  Both were left alone: the file is mid-edit by the owner, and the 6 October
  ruling was that existing W-labels in the handover stay. The release script
  now excludes those screenshots **by folder name rather than by number**, so
  the renumber cannot make it drop the wrong widget's shots.
- `memento/systemPatterns.md`, `memento/activeContext.md`, `memento/progress.md`
  and `memento/productContext.md` describe W19 as Alerts & Actions. They arrived
  with the 16 October pull and are another workstream's notes, so they were
  flagged rather than edited.
- The release script had **already been broken by the 13 October commit** that
  commented out the alerts2 rows: its end anchor expected a live row. Fixed in
  passing, since the renumber touched the same lines.
