## Logic that must not be lost
- **Paging is display-only.** Sort and filter apply first; the Total row and the KPI headline cross-foot the FULL scoped set, never the visible page. Page resets to 1 on any scope, sort or breakdown change and is clamped on render.
- **Breakdown follows scope.** "total" = one ring / one line. "group" = By Account Type at All Accounts, By Account at a selected type. There is no all-accounts by-account view.
- **Compare To:** week / month / fiscal period / quarter / fiscal year / calendar year. The fiscal period comes from the org's fiscal calendar (Time Window Module), between a month and a quarter. Compare To drives the KPI delta pill and the table's Trend % column; there is NO comparison overlay on the Trend chart (the Step 4 doc says otherwise; the build is followed and the conflict stays open).
- **Chart click drills into scope:** a type series (slice or line) sets the scope to that type and flips the breakdown to By Account; an account series is inert. Row click opens the account pop-up; nothing jumps out of the widget (no module screen exists).
- **Historical balances** for Trend and non-current Compare To are computed on demand for v1; the tie-out against `DHAccount.CalcBalance` is a backend concern.

## Account type naming, and legacy alignment (owner rulings 2026-10-01)

### Naming: "Product" was built, then reverted

The term was challenged on the grounds that in accounting an "account type" is the chart-of-accounts classification (asset, liability, equity, revenue, expense), and the GL module next door uses it that way, whereas `DHType` actually holds a set of customer-defined terms that accounts inherit: interest rate, compound or pay out, accrue frequency, duration in months, renew at maturity, allow additional deposits, the penalty block and the GL liability / interest / penalty postings, with `KeepTermsInSyncOnAllAccounts` pushing them down onto every account. In banking that is a product, and the term would have covered Loan Processing's identically named page too.

"Product" was implemented across the widget and then **reverted on the owner's ruling: every other Deposits on Hand screen says Account Type, so the module has to read one way.** Consistency across the module beats a better word in one widget.

**Final term: Account Type**, in the UI and in the code (`DEPO_TYPES`, `depOTypes`). If the term is ever revisited it has to move everywhere at once, including Modify > Account Type Information and the Loan Processing equivalent, not widget by widget.

### Legacy logic this widget is aligned with

`Shelby.Web.Financials/DataPanelControls/DepositAccounts.ascx.cs` is the widget being replaced; `DepositsOnHand/AccountTypeInformation/Default.aspx.cs` with `DHTypeRepository.GetAllByCurrentContextFiltered()` is the maintenance page. They never matched each other, which is why comparing them was confusing: the maintenance page filters by Group plus a wildcard Description, while the widget dropdown is a flat list of every type under the current bank account, ordered by name, with "Show All" pinned first on an empty value.

### Logic that must not be lost
- **Account types are configured records, not labels read off the accounts.** The scope list comes from `DEPO_TYPES`; the donut still derives from the accounts, so a type with no accounts gets no slice, exactly as the legacy pie behaves.
- **A type with no accounts renders a scoped empty state with the header intact**, so the scope chip stays reachable. The headline reads $0, which is what legacy shows (0 accounts, $0.00).
- **Inception sorts on a month-year key**, not the display string, so "Sep 2020" does not sort before "Apr 2023".

### Defects found and fixed along the way
- **A label the rename missed, twice over.** The Trend legend heading carries its own label, `(mode==="type"?...)`, separate from the `legendLabel` the Distribution donut reads. The first rename pass caught the donut's string and the lower-case isolate-button string but not the capitalised Trend one, so Trend read "ACCOUNT TYPES" while everything else read Product. The driver had not caught it because its vocabulary check only rendered each row in its default view, and all three default to Table. The check now sweeps 3 sizes x 3 views x 2 breakdowns and names the Trend legend and isolate button explicitly. The same widened check guarded the revert.
- **The scoped empty state was a dead end.** It first returned before `depOHeaderBlock(w)`, taking the scope chip with it, while its own copy told the reader to "pick another account type above". Moved after the header; the driver asserts the chip survives.
