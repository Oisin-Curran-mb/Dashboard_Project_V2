## Logic that must not be lost
- **Five ranges, in order, always rendered:** Current (not yet due), 1-30, 31-60, 61-90, 90+. A range with no balance is a muted, inert $0.00 row, never a filter control; arcs are drawn only for ranges holding a balance.
- **The loan-type filter drives everything:** buckets derive from the filtered set, so the donut, chip counts, header total, past-due pill and Glance aging bar all re-read against the selected type.
- **The ranges are the filter, not a grouping:** one flat list; the donut legend (Detail) and the chip row (Explore) filter it; tapping the active range again clears the filter.
- **Sort:** Days past due column removed; default Amount due descending; four sortable columns (Account, Borrower, Last payment, Amount due). Last payment keeps its dormancy flag.
- **Explore** has a Table / Pie segment (Table default); **Detail** shows the list beside the donut, no toggle.
- **Backend flag carried:** the aging-range figures assume the legacy oldest-first payment allocation; the modern API does not replicate it yet.
- Her "Aging and risk" panel is carried as `lonFAgingPanel`, defined and uncalled, so a rollback is one line (release-gate housekeeping: delete if still unused).
