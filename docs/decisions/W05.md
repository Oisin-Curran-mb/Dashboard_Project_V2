## Logic that must not be lost
- **Bands:** Current is `days <= 0` (not yet due); 1-30, 31-60, 61-90, 91-120, 121+. Overdue headline = every invoice with `days > 0`. An empty band still renders as an inert row so the band's existence is visible.
- **Two fetches only:** Revenue Center and Source chips reload (skeleton); every other control is a client re-render.
- **Customers panel:** seven per page, sort Biggest amount (default) or Oldest balance (each customer's most-overdue invoice), ties fall to the other key; page resets on any filter or sort change and is clamped on render.
- **Drill modal:** flat invoice table (Customer, Bill To, Due Date, Invoice #, Days Past Due, Outstanding); per-row checkbox keyed by invoice number, no select-all; Confirm is always enabled and reveals the dev-intent note "Move to unposted transactions" with the selected count. The transaction type behind it is an open SME/API item and is deliberately not invented.
- **Open items carried:** Attachments / Note / Payments tab data sources unverified (Feargal); action-list flag C1 (six bands) awaiting formal closure; the overdue pill tooltip wording vs `days > 0`.
