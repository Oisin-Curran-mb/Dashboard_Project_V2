Owner: "I want you to fix the name to OC version and fix the clear issue with OC version ... is it possible to show pledges and gifts as two separate colors in the progress bar and then in pop up give the options to filter gifts and pledges and search bar to find one gift or pledge ... check to see history on it." Evidence and reasoning: `W17 Gifts Pledges - Thought Process and Concept Review (2026-09-28).md`. Work order: `W17 Gifts Pledges - Rebuild Plan (2026-09-28).md`. Builds `_tools/one-off/build-w17a-model` through `build-w17k-driver-tail`, all dated 2026-09-28.

### What the code settled

The legacy system holds two models and the owner's two instincts each described one. The dashboard panel is pledge-only: `GFPledgeRepository.GetWidgetData` walks `GFPledge.GFHistoryDetails` on `PledgeID`. The parallel purpose-wide path, `GFPurpose.GFHistoryDetails` on `PurposeID`, exists and is simply unused by that panel. A real goal does exist, but it is `GFCampaignDetail.Goal` per dated period, and the Campaign screen measures it against every `CampaignID`-tagged gift.

Our build had blended the two: a campaign-style goal measured against pledge-linked receipts only. The data does not support that. The owner's ruling to count both resolves it.

### Decided

- **The row unit is the purpose**, not the campaign. A campaign is a real and different entity, many per purpose, each with dated goal periods.
- **Received carries both parts**, named **Pledge payments** and **Other gifts** in the bar, the legend, the ledger and the pop-up summary. The column keeps the name Received.
- **The invented per-purpose goal is retired**, with its 75 and 100 per cent bands, labels and colours. No such field exists per purpose.
- **Pledge Total, Pledge Due, Due Remaining and Percent Due are unchanged.** All four already matched the legacy panel's formulas, and keeping them is what lets the table reconcile.
- **Every money figure obeys the date window, and the default preset has no start date.** This was the one call made on the owner's behalf, and it is the reason the default still reconciles with the shipped panel figure for figure on the pledge-payments subtotal. A start date with an unwindowed Pledge Due would make a fully paid old pledge look catastrophically behind.
- Presets: Gifts received through (default), Year to date, This quarter, This month, Custom dates. The word "fiscal" is avoided, on Edward Eoff's instruction for the sibling widget: it implies the General Ledger year, and gifts run on the calendar.
- **"Paid in full" on a pledge that is merely current becomes "Up to date."** The old label was wrong.

### Defects fixed

- **Per-pledge pace was all-or-nothing.** Received counted a pledge's whole paid amount only if its date fell inside the window. It now sums gift lines.
- **The pop-up did not redraw on expand.** `gopen` called `render()` only, and the modal is body-mounted, so opening a row did nothing. Present since the 25 September port. This is the defect the owner remembered.
- **The Detail drill was window-blind.** It paced every donor pledge over all time while the purpose row above it obeyed the window, so at a narrow preset the two levels of one widget disagreed. Both now read the same window.
- Reference is fed from the real fields, `GFHistory.CheckNumber` and `ReceiptNumber`. This corrects Part 10 of the review document, which wrongly said the column had no source.
- Dead code removed: the retired donut, the goal panel, the pre-v1.2 layout branch. The two undeclared classes declared. Nine ledger rules root-scoped. `gpf-seg-other-tag` declared from the same token as the bar's other-gifts segment.

### New in the data

Unpledged gifts per purpose, gift media, motivation with code and name, and references. All real fields on the gift row. A seventh purpose, Memorial Gifts, has gifts and no pledge at all, which the old widget could not show. Open: whether the dashboard endpoint can supply media and motivation. The fields exist; the API spec does not request them yet.

### The pop-up

The "donors behind pace" modal is replaced by a giving ledger: everything that came in for the purpose, largest first, with a type filter (All, Pledge payments, Other gifts), a search box matching donor, pledge and reference, and each row expanding to its history. A pledge shows its gifts with date, how it arrived, what prompted it, reference and amount. The old modal duplicated W04 Remittance Pledges.

### Still open

- The real campaign goal, which needs a campaign-period row unit.
- Our W04 pacing basis differs from the legacy monthly step. Recorded in Part 10 of the review document.
- One stray edit: a `campaign` to `purpose` rename in the rebuild reached a comment inside Jo's own block ("capital campaign" became "capital purpose"). Her code is unaffected and her block is deleted at finalisation.

## 28 Sep: finalised on the OC version (owner)

Owner: "Gifts Pledges clean so there only OC and remove Jo and clean away code that no longer in use."

Jo's `gft` block, its CSS, its shell hooks and its registry rows are deleted. Ours keeps prefix `gpF`, takes over kind `gifts`, registers through `WIDGETS.register` like every other finished widget, and keeps only the three sizes. The four review fixtures (Summary Table, one purpose, single-purpose dataset, empty) left the demo registry; the driver builds those states itself, as W13's does.

The sixty classes our block borrowed from hers were copied into its own CSS as `gpf-*` first, so it declares everything it draws with. The CSS removal was done rule by rule rather than as a span cut, because her cluster housed two lodgers that had to survive: the `.mi-sub2` override that W01's popover also reads, and the shared `.pbar` run parked immediately after it.

**A regression of the copy-in, caught by the duplicate-selector lint and measured in the browser.** The copied rules were appended at the end of our CSS block, which inverted the cascade for four classes the block already declared. `.gpf-body` computed `display:block` from the copy and lost its flex column. Her cluster used to sit earlier in the stylesheet, and her selectors were one class less specific, so ours won twice over; after the copy both sides read `.gpf-root .gpf-*` and the later copy won. The copied rules are the base and now sit first.

The driver is renamed `w17-gifts.driver.js`. Section 13, which existed only to prove Jo's block was byte-unmodified, went with her block. 620 assertions.

The side-by-side comparison tab was retired in the same commit: W17 was the last undecided widget, so `CMP_ROWS` is empty and there is nothing left to compare. Its driver went too. The single-widget review viewer is untouched and now lists all sixteen card widgets.

## 28 Sep: the pop-up, and the header trim (owner)

### "fix the pop up to work as it is intented"

Two faults, both found by screenshotting the pop-up rather than reading its markup.

**The ledger clipped 48 of its 58 rows.** Measured: 5,786px of rows inside a 410px box carrying `overflow:hidden`, last row at y=5842 against a modal bottom of 706. The clip came in with the sixty classes copied from Jo's block, where it was correct: that container was the in-card drill, paged at twenty rows, and the clip kept its rounded corners. The ledger is not paged. Earlier verification counted the rows in the DOM, found 58 and missed it entirely, which is the lesson worth keeping: a row that exists is not a row you can reach. The ledger now has its own scroll container, so the summary, the type filter and the search box stay pinned while the entries scroll, and the column header sticks so they stay labelled. The in-card drill keeps its clip.

**A pledge showed its payments but not its schedule.** The rebuild plan called for both. A pledge behind pace showed what had arrived with nothing to compare it against, which is the one thing its Due Remaining asserts. A pledge's expansion now opens with its instalment schedule, stepped exactly as `gpFPledgedIn` steps it, so the schedule cannot disagree with the pace figures beside it. Each instalment says whether it has fallen due by the end of the current window: 728 of the 3,990 instalments in the fixture are still in the future, so both states are real.

Two further defects surfaced in the same screenshot, both mine from the ledger build:

- **A giant "UNDEFINED" in the status column.** `gpFDonorChip`'s icon map carried `full`, which nothing produces, and was missing `current`, which is what an up-to-date pledge gets, so `ICON(undefined)` emitted a glyph span containing the word. Invisible to any assertion about the row's figures.
- **The columns did not line up and the text was centred.** The row carried `gpf-grow`, the gift-list row, which is redeclared later as a three-column grid and so overrode the donor row's flex layout; the row's six cells wrapped onto two lines. The row is also a `<button>` and nothing reset the browser's centred text. It now has its own class for what it actually needs.

### "just the dates ... remove the download button ... remove gift and pledges in the glimpse version"

- **The date chip shows only the dates.** "Aug 19, 2026", or "Jan 1 to Aug 19, 2026" for a windowed preset. The full sentence is kept in the aria-label and in the pop-up subtitle, where there is room for it.
- **The header export button is deleted**, with its handler. The in-card drill keeps its own purpose-scoped export, which is a separate control further in and was left for the owner to rule on.
- **Glance drops its "Gifts and Pledges" chip.** The card is already titled Gifts Pledges, so the chip repeated the title inside it.

Two things had to follow, because the trim exposed them:

- The chip printed the word **"event"** beside its calendar. `.gpf-datechip::before` was copied in to swap the shared filter-chip glyph for a calendar, but that shared glyph is gated on `[data-action]` and this block's chips carry `data-gpf`, so there was nothing to override and the rule added a text-only pseudo-element with no icon font behind it.
- **Glance still did not fit**: 133px of stack in a 103px box, clipped at 137px, which is why the last line was cut through its own text. The pill row and the caption each wrapped to two lines. Both are now held to one line and scroll sideways, which is the pattern W15 Bank Balances settled on for the same problem, scoped to the Glance tier alone. Glance now measures 87px in 87px. The caption also takes a compact wording at Glance only; the full wording stays at Explore, Detail and in every screen-reader line.

Driver section 14 holds all of it: 677 assertions for W17, 3,126 across the suite.

## 28 Sep: the table opens the pop-up, and the bar's two segments (owner)

### "In the table view, instead of expanding the row it should be a pop up"

A table row opened an inline donor drill below itself: the purpose's pledges at twenty to a page, with a pager and its own export. It now opens the giving ledger, the same pop-up a Giving bar opens, so a purpose behaves the same way wherever it is selected and there is one place that answers "what is behind this".

The whole inline drill is retired rather than left defined: `gpFDonorPanel`, `gpFDonorHead`, `gpFDonorRowHTML`, `gpFPager`, `gpFDonorRows`, `GPF_PAGE_SIZE`, the `open`, `ppage` and `export-donors` handlers, the per-row `gpFExp` and `gpFPage` state, and eleven orphaned CSS rules. `gpFDonorRows` went too: the drill was its only caller, so keeping it would have been product code alive only because a test called it. The driver derives the same list from `gpFDonorsFor` and `gpFDonorPace`, which the ledger uses.

That also answers the question left open when the header export was removed. There is no export stub left anywhere on this widget.

What the retired section 5 of the driver proved, and where each property went:

| Proved | Now |
|---|---|
| the drill opened on page 1 at twenty a page | retired with the pager; the ledger is not paged, and its scroll container is asserted instead |
| the purpose figures never moved while paging | asserted against the ledger's summary, computed the same way |
| the donor sums rolled up to the purpose row | kept, against the ledger's rows and the pace arithmetic |
| each purpose paged independently | retired with the pager |
| the drill was ordered most behind pace first | the ledger orders by amount, largest first, because it lists gifts and pledges together and "behind pace" means nothing for a gift |

### The bar's two segments

"for the gift it should be straight line on the left and curved on the right and when you hover over it show how much for pledges and when hover over gifts it would show gift amount"

Both segments inherited one fill rule, rounded on the left and square on the right. That is right for the pledge payments, which start at the track's left edge, and backwards for the other gifts, which butt against the pledge segment and end in open track. The gifts segment is now square on the left and curved on the right.

No special case is needed for a purpose with gifts and no pledge, where the gift segment starts at zero: the track carries the radius and clips, so that end still reads as rounded. The legend swatches take the same two classes, so they are squared back explicitly, or they would have inherited the bar's asymmetric corners.

Each segment names itself and its amount through the shell's delegated tooltip, in whole dollars, matching the line printed under the bar. Verified by dispatching a real hover: the dark part reads "Pledge payments: $72,000" and the light part "Other gifts: $9,800" on Organ Restoration, which is what its foot line says.

## 28 Sep: the ledger's filter and Type column (owner)

"for the pop up. the filter should be 'all, pledges, gifts'. type should either be pledge or gift."

**The filter** reads All, Pledges, Gifts. Labels only: the values behind them were already `all`, `pledges`, `gifts`. The summary strip above keeps "Pledge payments" and "Other gifts", because those name money figures under the 19 August ruling, not row types.

**The Type column was mislabelled.** A gift row showed "Other gift", which is a type. A pledge row showed its pace status, "Fully paid" or "50+ days behind", which is not. Both rows now show a tag reading Pledge or Gift, tinted from the same two tokens as the bar's segments, so the column and the bar agree by colour.

The pace status is moved, not dropped: dropping it would lose the one thing that column was actually telling you about a pledge. It sits in the donor cell's sub-line beside the pledge reference, and the word "Pledge" left that sub-line since the Type column now carries it, so it reads "FRNKSTOK-19" then the status rather than repeating itself. A gift's sub-line drops to "No pledge" for the same reason. A pledge row's aria-label gains its status, so the reading order matches the screen.

Checked in the browser: the filter partitions cleanly, 46 pledges and 12 gifts against 58 unfiltered, and each filtered view shows only its own type tag.

## 28 Sep: it is a gift, and the caption goes (owner)

"again it should be a gift and not other gift." Six visible strings carried "other gifts": the bar's hover, the split line under each bar and in the headline, the legend, the view-toggle tip and the pop-up's summary strip. All read "gifts" now.

The word "other" was doing a job in the model, where `other` means a gift with no pledge behind it, and it stays there: the data key, the class names and the comments are unchanged. On screen it was only ever needed to tell the two bar segments apart, and "Pledge payments" against "Gifts" does that without it. The driver asserts this split directly: no visible string says "other gift", while the model keeps its own name for the distinction.

**"remove non needed text."** The Giving view's caption is deleted. It read "What each purpose has received, most received first. The bar shows pledge payments and gifts separately. Select one to see every gift and pledge behind it." Three sentences describing what the bars, the legend and the rows in front of you already say.

The Summary Table's own caption is **left alone**, and flagged rather than removed on a guess. It explains how Pledge Due and Percent Due are derived, which is reference rather than instruction, and it sits on the view the owner was not looking at.

Two CSS rules went with the caption: both existed only to place the export button inside it, and that button was removed earlier the same day.

**The about text was also corrected here**, because it still described the widget before the rebuild: a goal that no longer exists, Received as pledge-linked only, and opening a purpose to reach an inline donor drill that the pop-up replaced.
