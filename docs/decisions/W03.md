## What the build did
- **Deleted** Jo's `payroll-mb` (`prF`) block (203 lines) and her retired v1 `payroll` (`pr`) block (113 lines), their shell hooks (content, popovers incl. the v1 `prperiod` / `pr-scope` popover blocks, trigger, about, click ×7 + 2 hooks), her 6 registry rows and label comment, and the payroll-only `.pr-*` / `.prf-*` stylesheet runs (30 lines). Every deleted name checked for zero remaining code references; nothing outside payroll code used any of it.
- **Kept and rewired in the shell:** the scoped drill modal (`renderModal`'s `modal.scoped` body) picks its body by kind inline, so it now reads `kind==="payroll" ? prOContent(...)`; `renderOverlay` gives the period popover its `.pop-period` width by our popover type instead of the v1 one.
- **Stand-alone CSS:** 20 `w03-` copies of the shared payroll rules the block uses (+ our own 20 rules, with the shared classes they referenced renamed); five unstyled hook classes (`pr-scope`, `pr-emprow`, `pr-empnest`, `pr-ptline`, `pr-ptnest`) renamed `w03-`. The block references nothing named `pr-`.
- **Registry:** kind `payroll-oc` -> `payroll`; three live rows titled "Payroll Distributions" (Explore, Glance, Detail); the Overtime-only, one-distribution and no-history variants stay as driver fixtures. `CMP_ROWS` row and `CMPNOTE_` entry removed; the comparison tab holds 11 widgets.
- Registered: `WIDGETS.register("payroll",{content, about, click, pops:{prO-period, prO-scope, prO-pt}})`; block placed before the registry; wiring how-to comments removed (D10).
- Drivers: `w03-payroll-oc.driver.js` replaced by `w03-payroll.driver.js`; `H.headMatchesBody` now counts top-level cells only (a sort button inside a header cell is part of that cell); the map-driven cmp driver and W18's guard adjusted for removed kinds; three `-mb` drivers now locate the shell's empty fallback from `contentHTML` onward.

## Auto-fixed defects
- **Follow-up (found at W04, 25 Sep):** this build renamed the period popover's date inputs to `w03-date-input` while the shell's `change` / `focus` / `focusout` listeners still looked for `pr-date-input`, so custom From / To dates had stopped applying. The handling now lives inside the W03 block (its own listeners); the driver asserts a From date lands on the widget and the range becomes CUSTOM.
- None in the widget itself otherwise. All three payroll tables (Explore, Detail, drill) pass D12 (header cells carry their column's classes).
