## Why the code is still here

**W19 Pending Actions renders inside this widget's class families and declares
none of them itself**: `.alb4-root`, `.alb4-tabs`, `.alb4-panel`,
`.alb4-xwide-wrap`, `.alb4-detail-*`, `.alb4-xw-left-panel`, `.al-cat`,
`.al-count`, `.al-item`, `.al-modal-hd`, and the whole `.al2-dp-*` detail-pane
family. Deleting this block today would strip the live widget of most of its
styling.

That dependency is pinned in `w20-alerts.driver.js` rather than left as a note,
so removing the block fails loudly.

**Do not rename those classes to `pa3-*`.** It was tried on 13 October 2026 and
broke the right-hand detail pane;
`_tools/one-off/fix-pending-actions-2026-10-13.py` opens by reverting it.

## What the driver asserts now

The structural, data and rendering checks are unchanged from the W19 era: the
four banners, the region sizes, the registration, 6 categories and 15 items
(4 critical, 11 warning), the tab counts, the accordion, and that every item
pop-up builds including the two configs that used to crash in the source.

What changed with the scrapping:

- **No live registry row** with kind `alerts` or `alerts2`, where it used to
  assert two. All four rows are asserted present but commented out, and
  `W20:false` is asserted.
- **The interaction paths are no longer exercised.** `aloHandle` opens with
  `var w=find(id);if(!w)return false;`, and `find()` reads the registry, so
  every action declines while the widget is switched off. Asserting the old
  behaviour would mean un-commenting a row the owner switched off. What is
  pinned instead is that the actions **decline cleanly rather than throwing**,
  with that guard quoted in the driver so the cause is not re-diagnosed later.
- The rendering checks run against a widget object built in the driver, copied
  from the commented-out rows, because there is no row left to read.

## How to retire it properly, when that is wanted

1. Copy the borrowed classes into W19's own CSS region under `pa3-` names,
   **rule by rule**, keeping them in base position ahead of W19's own
   overrides. (A span cut would take the Alerts-only rules with them, and
   appending the copies after W19's own rules inverts the cascade — that exact
   mistake was made and measured on W17 on 28 September.)
2. Update W19's markup to emit the new names. Expect the detail pane to be the
   fragile part; it is what broke on 13 October.
3. Only then cut this block, its two kinds, its commented rows and this driver.
