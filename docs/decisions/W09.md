## Logic that must not be lost
- **Per-day grain:** every line is one `OffDate`; multi-day requests are shown, counted and approved day by day. No schema change needed.
- **States:** Pending and Approved stored; **Outstanding is derived** (pending and dated strictly before today); approving clears it. Rejected does not exist.
- **Glance figures partition the pending set:** Pending EXCLUDES outstanding, so the two never double count.
- **No bulk approve by design** (conflicts with Jo's dossier 9 / 11.1; the conflict is recorded, not resolved).
- **Calendar filter is Department only**; Group by belongs to the queue. Markers colour by status, never by group.
- **Open API gaps carried, never invented:** approval-authority filter (confidentiality: a supervisor must see only their departments), an inline approval write endpoint (`PUT /entries/{id}/approval` is new), custom leave-type names from `PRCompany`.
- **Known defect carried:** the Explore "N more in Detail size" note counts the withheld person's day-lines, not people (owner's call whether to fix).
- **Shell gap:** no amber token exists; Pending's amber is declared locally (`--ptof-st-pend`).
